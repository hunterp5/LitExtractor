# LitExtractor

LitExtractor is a desktop application for finding chemical structures and related information in patent and research PDFs. Its PySide6 interface presents extracted molecules and reactions for review; OpenChemIE handles model-backed document extraction, and RDKit parses, validates, enriches, ranks, and depicts structures.

## Features

- Extract structures from document figures and chemical entities from text.
- Process figure–label coreferences by default to associate structure figures with labels; reactions are optional.
- Review structures, SMILES, identifiers, source pages, formulas, molecular weights, and InChIKeys.
- Select a molecule to view its structure, patent crop on a white canvas, and metadata in a fixed-width preview pane.
- Read data tables (activity, yield, properties) and match their rows to structures by label, with a Tables tab to confirm, choose or correct each match.
- Extract several PDFs, or a whole folder, in one go; each gets its own result tab.
- Merge duplicate molecules by InChIKey.
- Export molecule data to CSV, SDF, or SMILES, and table data as a long CSV or as each table as printed.
- Choose CPU or CUDA for model inference. CPU is available immediately; CUDA detection runs in the background after the window opens.
- A simple centered workspace message shows when to open a PDF and reports initial extraction progress.
- View recommended software and research citations from **Help → Citations**.

OpenChemIE models are large and can be slow on CPU. Model weights may be downloaded the first time extraction runs. The GUI can still start when optional extraction dependencies are unavailable; it reports missing runtime components when extraction is requested.

## Requirements

- Python 3.10 or 3.11 (the versions currently documented and tested for this project).
- A compatible PyTorch 2.x and torchvision installation. CUDA is optional.
- Poppler tools (`pdfinfo` and `pdftoppm`) available on `PATH` for PDF page rendering through `pdf2image`.
- Network access on the first model-backed run unless the required model weights are already cached.

## Installation

### 1. Create and activate a virtual environment

From the project directory, on Windows PowerShell:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
```

On macOS or Linux, use `python3 -m venv .venv` and `source .venv/bin/activate` instead.

### 2. Install PyTorch

Install a PyTorch 2.x and torchvision build that matches your operating system and hardware. For a CPU-only installation:

```powershell
python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
```

For CUDA, use the command generated by the [official PyTorch installation selector](https://pytorch.org/get-started/locally/). Install PyTorch before the remaining packages so the selected build is retained.

### 3. Install the application and extraction stack

```powershell
python -m pip install --no-deps -r requirements.txt
python -m pip install -e ".[dev]"
```

These two stages are intentional: the pinned OpenChemIE revision declares `torch<2.0` in its upstream metadata, which conflicts with the PyTorch 2.x build used by this project. The first command installs the curated runtime and model package pins without resolving that incompatible metadata; the second installs LitExtractor in editable mode with its development tools. This is the shortest safe workflow with the current upstream pins. Avoid installing OpenChemIE separately or replacing the first command with a plain `pip install -r requirements.txt`; a one-step resolver-based install is not reliable until the upstream metadata conflict is resolved.

### 4. Install Poppler

Install Poppler using your platform's package manager or a trusted platform build, then make sure `pdfinfo` and `pdftoppm` are on `PATH`. See the [`pdf2image` installation guide](https://pdf2image.readthedocs.io/en/latest/installation.html) for platform-specific instructions.

## Run

Logging can be configured with `LITEXTRACTOR_LOG_DIR`,
`LITEXTRACTOR_LOG_LEVEL`, and `LITEXTRACTOR_LOG_TO_FILE`.

From the project directory:

```powershell
python -m litextractor
```

After an editable installation, the `litextractor` console command is also available.

## Use the application

1. Open one or more PDFs with **File → Open PDFs…**, or every PDF in a folder with **File → Open Folder of PDFs…** (subfolders are not included). Several PDFs are extracted one after another with the same options; each result tab appears as soon as its PDF is done, a PDF that fails does not stop the rest, and one summary lists failures and warnings at the end.
2. Select the sources to process: figures, text, coreferences, reactions, or data tables.
3. Optionally set a page range and a device.
4. Start extraction and review the results in the Molecules, Tables and Reactions tabs (Reactions appears only when reactions were extracted). Each extraction is kept in its own result tab; right-click a result tab and confirm to delete it.
5. Review table data in the **Tables** tab (see below).
6. Export molecule results through **File → Export**. Exports use the currently active result tab.

### Table data

Tables are read from the PDF's text layer while figures are detected. Tables printed across several pages, or as side-by-side panels repeating the same columns, are joined into one table with one row per compound. Tables of structures are not listed: their structures appear on the Molecules tab instead.

Each row is matched to a structure by its key column (a header such as "Ex No", "Compound" or "Drug", else the column whose values match structure labels). Structure labels come from the text printed below each structure, or beside it in a table row, taken from the PDF's text layer, or read by OCR when the figure is a picture. The **Structure** column of the Tables tab shows each row's match:

- a name: a suggested match; amber when it was found only after ignoring common OCR confusions (1/I/l, 0/O);
- "*n* matches": several structures carry the label; right-click to choose one;
- ✓ name: confirmed, or linked by hand;
- —: no match; right-click to link a structure.

Double-click the table image to open it full size in a zoomable window (Ctrl+scroll or the zoom buttons) that can stay open beside the grid. Double-click a cell to correct it; correcting a key cell matches the row again. Right-click a column header to show that column on the Molecules table (as "Table 3 · IC50 (nM)") or to match rows by another column. The detail pane lists the table rows linked to the selected structure; click one to open it in the Tables tab.

A table whose columns are several lists of compound names (for example "Reversible" beside "Irreversible") gets no key column, because pairing its names by row would be wrong; choose one by hand if its rows do describe one compound each.

Table data is exported three ways from the **File** menu:

- **Export CSV / Export SDF**: the columns shown on the Molecules table are added to each molecule (empty while a row's match is ambiguous).
- **Export table data (long CSV)**: one line per structure, table row and column, with the value as printed, a parsed qualifier, number and unit where the value is a plain measurement ("<0.1" in an "IC50 (nM)" column gives "<", 0.1, nM), and how the row was linked. Unlinked rows are left out.
- **Export tables as printed**: one CSV per table in a chosen folder, every row included, with the linked structure, its SMILES and the link status in front.

Each structure is read from exactly the box the molecule detector found; padding that box pulled neighbouring bonds and labels into the crop and made readings worse. Figure regions found by layout detection are widened by a fixed 8% before the figure is cropped, so structures at a figure's edge are not cut off. Table regions are not widened.

The **Confidence** column shows MolScribe's confidence (0–1) in each structure it read. Values below 0.5 are marked "(low)", shown in amber, and ranked after confident results; in testing these were mostly non-structures (protein images, numbered lists) or misreads, so check the patent crop before relying on them. Confidence is included in CSV and SDF exports.

The interface uses a single light theme and fixed structure sizes and fonts; there is no settings
menu or saved preferences. File pickers retain their native operating-system appearance. Use
**Help → Citations** for the application’s core technology references.

## Tests

Run the model-free default suite with:

```powershell
python -m pytest -q
```

The suite does not download model weights. Model-backed tests are marked as integration tests and can be run explicitly with:

```powershell
python -m pytest --run-integration -m integration
```

The end-to-end integration test and other tests needing real patent content use the local one-page sample `samples/ddr2_sub.pdf`. The sample is not distributed with the repository; tests that need it skip when it is unavailable. Other small PDFs are generated in tests that specifically exercise PDF parsing, the compatibility shim, or page slicing. Integration tests also require Poppler, cached or downloadable model weights, and the relevant extraction runtime.

Check Python style with:

```powershell
python -m ruff check litextractor tests
```

See [docs/code-audit.md](docs/code-audit.md) for the maintainability audit findings and remediation status.
